# Private boundary integration contract (implementation in progress)

Native session JSON will add `identityEpoch: String`: an opaque process epoch, equality only, **not** the existing generation/fingerprint and not an owner digest. It changes whenever private admission is revoked (including untrusted bootstrap), not on clearance-only changes. Never persist it or infer an account from it. Existing `generation` remains the content/clearance refresh signal.

`session.privateBoundary` request/observe exposes exactly `{phase: "UNKNOWN" | "TRANSITIONING" | "READY", identityEpoch: String, requiresConfirmation: Boolean, recoveryEligible: Boolean}`. The reset response uses the same mapper. No cookies, owner proof, or persisted digest is exported. `session.resetPrivateStores` requires `{confirmed: true, identityEpoch: <the displayed epoch>}`; rejection/cancellation leaves old data inaccessible and preserved unless the confirmed cleanup has already begun. Confirmation must explicitly say local drafts/offline/private caches will be deleted, and never be supplied automatically by Swift. Unknown provenance cannot be repaired by adopting current cookies. Public preferences/auth/recovery remain usable.

`recoveryEligible` is an in-memory admission signal, not persisted provenance or permission to delete. It starts false, stays false throughout reconciliation, reset, authentication mutation and non-cancellable old-writer drain, and remains false while an external browser mutation owns admission. Once that work has ended, UNKNOWN or interrupted TRANSITIONING publishes true; READY publishes false. Reopening an interrupted journal still preserves TRANSITIONING and private denial, but exposes explicit recovery after reconciliation drains. Reset rejects immediately rather than queueing behind an active coordinator operation; external ownership, explicit confirmation and displayed-epoch checks remain authoritative. Starting a mutation revokes older recovery epochs. No new Objective-C method or reset argument is required; this is an additive JSON payload field, tested through the production mapper.

Swift requires a valid Boolean eligibility field and only offers review/confirmation for UNKNOWN or TRANSITIONING when it is true. Missing/malformed eligibility fails closed. Revocation cancels the outstanding dialog even if the epoch is unchanged; re-enabling eligibility never resurrects that token. Cancelled tasks, cancelled dialogs, stale generations and stale displayed epochs cannot dispatch. Recovery read/observation never invokes reset. Success still requires authoritative boundary/session readback before private admission.

Auth-cookie rotation with nonempty stores is conservatively a changed owner proof: absent server-verified rebinding, deny old private data and require explicit confirmation. Clearance alone is not an identity change. Same verified cookie owner on relaunch preserves data. Genuinely empty installation may initialize only after every protected store is proven empty. A successful password/2FA login or attained login/one-tap browser goal may rebind a previously verified READY state only when the complete physical inventory was empty after old writers joined and remains empty at completion. That rebind preserves the new epoch and invokes no deletion. UNKNOWN/legacy/interrupted journals cannot acquire this capability through authentication. Shared/default callers do not opt in. See `build57-post-login-private-boundary.md` for reproduced transitions and verification limits.

Successful password/2FA auth JSON adds `privateDataStatus: "READY" | "CONFIRMATION_REQUIRED"` and `privateBoundary` using the existing boundary DTO, assembled after mutation-finally reconciliation. `status: "SIGNED"` still means authentication succeeded; it is not private-data admission. Consumers must explain preserved-but-locked local data without automatic reset. Browser consumers read the existing boundary after final close/drain.

Parent coordination required: NativeAccount integration is not owned by this agent initially. Route auth mutations through the graph coordinator rather than letting synchronous session publication precede cleanup. Swift may implement the above additive ABI, but it is **not yet a delivery claim**. See final status/evidence for which paths actually landed.
