Inject `NativeRootView().environmentObject(model)` into the scene's UIHostingController. **Root owns `.task { await app.start() }`**, not App.swift. ## Lifecycle and API

Shared transport/errors/JSON remain in NativeCore. Foundation adds exact integration-contract helpers, ObservableObject model/store and UUID route identity; IDs never become Double. NativeStore delegates cancellation/stale-operation suppression to the tested NativeRequestState and adds weak registration for immediate session invalidation plus unexpected-observation-end errors. Observe must be awaited in each screen's `.task(id: app.generation)`; one operation per store.

`start()` first calls real `site.get`, then independently observes `session.state`, `session.privateBoundary` and `settings.observe`. Public recovery/settings/auth are available as soon as the active site is known, even when private initialization is pending; queued deep links drain after initial session/settings emissions. Null initial session counts as a public bootstrap emission, never private admission. It calls real `app.foreground`; failures remain visible. `current` and `selected` are enum strings, not objects; a next-launch selection does not replace the active namespace.

Identity invalidation uses the backend's opaque **String** `identityEpoch`, equality only, never a cookie/fingerprint-derived fallback or persisted owner. A changed epoch (including signed-in A→B with an unchanged reload generation), invalid/null session, revoked private boundary or running-site change clears stores, cancels pending non-session requests, clears paths/sheets and advances local UI `generation`. Shared session `generation` remains available as the reload revision in `session`; advancing it for clearance alone does **not** remount tabs/editors or discard navigation. No automatic mutation retry.

`openLink` validates HTTP(S), credential-free URL structure, waits for site context, then uses NativeCore exact-host routing. Int64 IDs, post page and numeric floor fragment are preserved. Member names use real `search.resolveMember`. Cross-site/ordinary external links carry `Web` + `goal:EXTERNAL`; **NativeScreen handles only this explicit external case via NativeExternalBrowser/Safari** (no app-cookie injection). Other Web goals remain in NativeMediaScreens. Unknown native routes show an unsupported failure, never a generic web fallback. Challenge uses exact `CHALLENGE` goal; login uses the SignIn factory.

## Explicit private recovery and editor departure

`docs/swiftui-private-boundary-contract.md` is the backend-owned ABI. Swift requires `{phase, identityEpoch:String, requiresConfirmation:Bool, recoveryEligible:Bool}` and only admits private factories when phase is READY, confirmation is false, and session/boundary epochs match. UNKNOWN, TRANSITIONING, missing/malformed epochs and stream errors show `NativePrivateBoundaryRecoveryView`; public settings/auth stay reachable. Review/reset is available for UNKNOWN and interrupted TRANSITIONING only when the backend reports drained `recoveryEligible:true`; active transitions remain non-destructive. Eligibility revocation discards any displayed dialog, including same-epoch revocation/recovery. Swift never initializes provenance or synthesizes an epoch. Atomic backend publication and protected-store isolation remain backend responsibilities.

The root alert explicitly states deletion of local drafts/offline downloads/private caches. Opening recovery or refreshing never resets. `beginPrivateResetConfirmation()` captures the displayed boundary epoch and local identity generation; `confirmPrivateReset(token)` consumes a single-use dialog token and sends exactly `{confirmed:true, identityEpoch:<displayed>}`. Cancel/stale identity cannot dispatch. Generic `app.request("session.resetPrivateStores", ...)` is rejected. Reset success is followed by boundary readback; Swift never infers READY or adopts current cookies. Errors stay locked; no automatic retry/confirmation. Recovery strings are present in en/zh-Hans/zh-Hant.

All paths and the root sheet now have private setters. Root path bindings, outer Close, same-identity SignIn/challenge replacement and `resetNavigation()` use an awaited departure gate, with a navigation revision/identity fence and single-flight removal. `NativeScreen` injects `EnvironmentValues.nativeDestinationID`. Editors register through `registerDismissal(destinationID:close:revoke:)`; missing editor registration denies removal. Temporary pushes/tab switches do not close or unregister owners. `unregisterDismissal(destinationID:token:)` only removes the exact owner.

`NativeEditorRouteLifetime` in the expressly delegated `NativeEditorScreens.swift` connects the real EditorViewModel to that gate: commit marked text, surface unresolved draft/edit decisions, await model.close, refuse failed save/newer input. Decisions call the same navigation gate. On identity revocation the callback synchronously calls model.invalidate, **never close/flush**; root drops private UI immediately while the drain agent's independent file leases wait for actual platform termination. Sheet swipe is disabled if any editor remains anywhere in that sheet stack, including beneath pushed screens. Source-file drain uses the separate contract in `swiftui-request-drain.md`, not Swift task completion.

Foundation tests compile the unchanged production EditorViewModel/EditorState and the actual production route registration class with a test-only EditorFocus substitute. They execute real app.open/dismissSheet/updatePath/identity callbacks against controlled transport, plus production CallbackNativeTransport with separately signalled termination. UI rendering is excluded only under FOUNDATION_EDITOR_TESTS; the combined signature gate compiles the real Editor screens and Foundation together. The older standalone Editor signature adapter needs the new Foundation API or should use this combined gate.

## Appearance

Uses native TabView/NavigationStack/Form/List surfaces; system chrome adopts Liquid Glass on iOS 26. Recovery actions use genuine `.buttonStyle(.glass)` with iOS 26 availability and bordered older/reduced-transparency fallback. Long-form content has no custom glass. Theme/language/custom/preset accent, e-ink light/monochrome treatment, Dynamic Type-preserving font scaling and reduced motion are applied at root and sheets. SwiftUI locale updates Text resources; domain strings built with `String(localized:)` remain subject to their own localization behavior.

References: Apple's `Applying Liquid Glass to custom views` (standard components use glass), `PrimitiveButtonStyle.glass`; inspected current official documentation. Native semantic Dynamic Type sizes avoid scaleEffect clipping. Android Material palette variants are **not** recreated as a complete Material tonal system: native chrome uses original primary accent tokens, system contrast surfaces; SOFT/VIBRANT/EXPRESSIVE/NEUTRAL variants need capability/UI reconciliation before claiming exact visual parity.
