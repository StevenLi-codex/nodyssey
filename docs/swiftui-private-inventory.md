# iOS private-store and writer inventory

## Contract and verification scope

Unknown or interrupted provenance **preserves physical data and denies private use**. A cookie identity is not evidence that it owns a legacy store. Account A → B revokes access; it does not authorize deletion. Only `session.resetPrivateStores` with `confirmed: true` and the currently displayed opaque `identityEpoch` may run the private cleanup inventory. Same verified owner survives a close/reopen. This inventory supplements `swiftui-private-boundary-contract.md`; it is not Apple release acceptance.

`python3 iosapp/tests/native_session_security_test.py --graph-integration --repeat 3` runs an integrated **JVM graph fixture**, not the actual Apple container constructor. It compiles:

- the exact `IosAppContainer.privateBoundary` inventory and post/comment/offline wrapper construction regions;
- current production boundary/provenance/barrier/wrappers and both composer sources;
- the whole production `NativeBridge`, `NativeAccount` and the existing platform-free browser fixture regions;
- exact native draft and offline dispatch cases plus production content/settings mappings;
- exact `BgTaskOfflineScheduler.launchPrivate` and `startDrain` regions.

It uses real temporary Preferences DataStore files, generated Room DAOs with bundled SQLite, `OfflineFirstPostRepository`, `RoomOfflineLibrary`, and real temporary offline files. DataStore scopes are cancelled and joined before reopening; Room is closed. Test I/O cannot contact the forum. Synthetic downloaded fixture bodies/comments/image rows are seeded through the real DAO; queue creation uses production native dispatch. All callbacks and request Job completion are awaited.

Platform substitutes are explicit: graph construction/dependency injection, cookie jar, filesystem adapter instead of Foundation paths, Coil cache containers, BG task submission and the network-availability result. Coil disk persistence, Apple cache interceptors/decoders, NSURLSession, actual BGTaskScheduler registration/expiration and Network.framework are **not** executed. The fixture source hashes and generated sources are retained in the printed unique artifact directory. Current production composers/boundary are compiled ahead of the prebuilt shared jar rather than trusting a stale wrapper implementation. No generated header, Native compilation, Swift linkage or Apple execution claim follows from JVM green.

## Writer scheduling audit

- `NodysseyApp` installs one loader, attaches the singleton scheduler to the boundary, reconciles before publishing the graph, and native foreground calls the existing scheduler instead of reconstructing a graph/Compose controller.
- `BgTaskOfflineScheduler.launchPrivate` resolves that graph, reconciles, rejects stale captured epochs, checks READY and enters `protect`. `startDrain` serializes restart with a mutex, cancels **and joins** the old foreground job, then launches replacement protected work. Background drain/maintenance also use `launchPrivate`; expiration cancels its job and completion reports from Job termination.
- The new controlled regression executes the exact production launch/restart regions against the real Room downloader: first network fixture suspends in `NonCancellable` finally, restart cannot launch replacement until that finally has terminated and its DataStore write landed; account change cannot finish reconciliation until replacement finally terminates; its interrupted queue is physically preserved until explicit reset. Deferred gates, not sleeps, establish the tested intervals.
- Offline bytes deliberately wait for terminal NSURLSession work under `NonCancellable` before checking cancellation. Apple termination/callback behavior is not reproduced by the JVM network fixture.
- Native Paging children/observer delivery are owned by a separate delivery regression. Raw profile/note/position/category repositories are not independently wrapped by this change. Native entry-point admission is therefore part of the security boundary; this audit does **not** certify arbitrary legacy Compose/direct graph access as safe.

## Proven wiring fixes (behavioral RED → GREEN)

1. Recent-board-only legacy installation was incorrectly considered completely empty and became READY. Added selective settings-history participant and one shared settings DataStore instance. RED artifact: `native-session-security-jvm-actewexw`; assertion expected UNKNOWN, got READY.
2. Orphan `title_regex_hits` was omitted from emptiness checks and cleanup. Added it to Room inventory and explicit derived-hit cleanup, preserving global keyword rules. RED artifact: `native-session-security-jvm-haeia03d`; assertion expected UNKNOWN, got READY.
3. Malformed report basket decoded to an empty list and was silently adopted as fresh. Check/remove its raw mixed-store key rather than relying on forgiving decode. RED artifact: `native-session-security-jvm-zn49file`; assertion expected UNKNOWN, got READY.

All three REDs are real production-inventory behavioral failures, not compiler errors or artificially withheld classes. The initial harness compile/dependency mistakes are not RED evidence.
